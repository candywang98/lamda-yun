## 执行纪律

- 每次只处理一张依赖已完成的任务卡；先阅读相关实现和现有测试，不根据旧计划重复建表。
- 所有卡片中的“新增接口/字段/目录”均为设计提案，实施前核对当时最新代码和迁移编号。
- 不通过删除失败测试、修改断言为永真、增加 skip、关闭认证或改用假数据完成任务。
- 单元测试、接口测试、真机预填、平台提交与公开发布分别验收。
- 本目录采用既有 ADR 0003 的 APK 直连主线；LAMDA/Edge 保留为诊断和历史兼容。正式改动架构约束文件前执行 V1-02。
- 外部素材库类型和平台账号权限尚未确认。先执行数据源盘点卡；不得从目录里的二维码图片推断使用飞书，更不得自造访问凭据。
- 没有 Git 历史；本次清理备份在 `artifacts/review-20260905/cleanup-backup.zip`。后续先建立只包含源码的版本检查点，不把凭据、设备数据库或媒体原件加入 Git。

每项任务输出 `artifacts/v1/<任务ID>/summary.md`、`commands.log` 和必要的脱敏验收证据。`done` 必须满足任务卡中的全部验收条件；有实现但未验收只能标 `review`。硬件已连接但权限未开时写明实际阻塞原因，不笼统声称“没有硬件”。

## 更新计划

`tasks.json` 是状态来源；Excel 是可读快照，修改 Excel 不会自动回写 JSON。完成验收后先更新 JSON 中的 status/owner/blocker/acceptance_evidence，再生成任务卡和表格。本轮制表脚本存放于 `artifacts/review-20260905/build-plan.py`、`build-workbook.py`；前者保留已记录的状态和负责人，后者需要 openpyxl。若变更任务范围/估算，也需同步生成脚本中的任务定义。

本次文件校验见 `artifacts/review-20260905/workbook-validation.json`；运行结果见同目录 `verification.json`。Excel 包含11张工作表、30张任务卡、12项审核问题和18组验收场景。
