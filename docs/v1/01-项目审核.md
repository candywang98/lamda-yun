# 项目审核：2026-09-05

## 结论

项目具备可复用的控制面、商品/素材管理和 Android 执行基础，但“一键从现有库发布到指定平台账号”的业务链路没有完成验收。最主要的问题是链路之间的接口和语义没有统一，而非缺少更多功能页面。

本结论对所审阅本地源码成立，置信度高；不代表线上服务器运行的版本已与本地一致。本机 8000 端口能返回含 111 条路径的 OpenAPI，但没有核对远端部署摘要，也没有读取用户业务数据来宣称外部库已接通。

不沿用旧“总体约 40%”估计。采用八个可演示业务里程碑：外部库同步、商品媒体可选、账号身份核对、真机正确预填、闲鱼发布、小红书发布、抖音发布、公众号发布。本轮没有证明其中任何一个完整端到端里程碑通过，故**本轮完整验收覆盖为 0/8；这不是源码完成率为零**。逐模块已有实现见下表，真实完成率待各卡验收累积。

## 按优先级审核发现

### F01 / P0：商品保存和闲鱼下发使用不同资源类型

`OperationsView.vue:saveContentRecord` 调 `createProduct/updateProduct`，将 Product ID 放入 `selectedPostId`。`dispatchSavedPost` 却调 `dispatchContentToXianyu(selectedPostId)`；后端 `services.py:dispatch_post_to_xianyu` 用 `repository.content(content_id)` 读取 Content。

推断：新建商品直接点击下发，可能返回找不到 Content；极端 ID 混用也有读错资源的语义风险。代码路径矛盾已确认，具体 UI 错误码尚未用真实业务数据复现。修复应建立 Product → 冻结快照 → 发布目标的正确入口，不把 Product ID 伪装成 Content ID。任务 V1-10、V1-14。

### F02 / P0：不能保证选中的就是任务媒体

`xianyu_publish.py:build_text_publish_task` 生成 `xianyu_gallery_select_0..N`；`TargetLocatorRegistry.kt` 将它解析为第 N 个“选择”节点。`MediaDeliveryCoordinator.kt` 虽记录导出的 URI，但配方没有消费 URI 与选择节点的对应关系。

推断：已有照片、系统相机入口、倒序排序或其他应用新写照片可能改变索引，导致顺序颠倒或选错图片。尚未做真机错图复现，因此记为高风险设计缺口。验收必须混入干扰图片，逐张核对所选内容，不能只验“图片数相同”。任务 V1-18。

### F03 / P0：预填完成不能算商品发布成功

`xianyu_publish.py` 最后是截图与 `XIANYU_PUBLISH_FORM_READY`；下发接口明确返回 `tapsPublish: false`。APK 的任务成功只说明步骤完成。PublishTarget 的成功必须来自平台发布结果与内容身份对账，不能直接复制 MobileTask 的 `SUCCEEDED`。任务 V1-13、V1-20、V1-21。

### F04 / P0：当前 APK 不是可执行验收状态

ADB 读取到 OnePlus LE2100、Android 14；Companion 0.1.0/versionCode 1 为 DEBUGGABLE，最后更新 2026-09-05 19:08:17。已启用无障碍服务列表不含本项目服务。现有设备足以开始验收准备，但仍需确认绑定环境、启用服务、核对账号并建立受控任务。

闲鱼 7.27.90、小红书 8.50.1、抖音 39.6.0、微信 8.0.76 均已安装。安装微信不能证明具备公众号管理或接口权限。设备原始摘要见 `device.json`。本轮没有发布内容、改变平台账号、安装 APK 或调整无障碍设置。任务 V1-04。

### F05 / P1：媒体授权仅到租户，未与任务绑定

`mobile_service.py:media_manifest/download_media` 核查资产所属租户，未以 `taskId + deliveryId + deviceId` 验证该设备是否被授予该资产。已绑定设备可申请同租户其他已知 ID 的资产；是否超出预期权限取决于设备信任模型。首版按最小授权设计，限定下载清单、绑定快照哈希并校验过期/撤销。任务 V1-17。

### F06 / P1：架构、文案和实现互相滞后

旧架构要求设备动作经 LAMDA，已接受 ADR 0003 又确定 APK 本地无障碍执行；README 仍以 mock/Edge 为主要说明。Web 文案称没有媒体投递，而 APK 已有对应代码。把“新建 Product 表/媒体投递从零实现”继续列为未开始会重复开发。先统一 ADR、能力名称和文档入口，保留已实现资产。任务 V1-02。

### F07 / P1：工程质量门未全部通过

本轮原始结果：Ruff 24 个问题、format 27 个文件、Pyright 12 个错误、Web lint 5 个错误。清理了测试中一个无用解构变量后应重新记录 lint 数量，不能拿修改前数量当修改后结果。

Pyright 错误主要在 Edge 调试协议及 Outbox sink 配置；不等于四平台主链都坏了，但会阻塞声明“全量验证通过”。测试名包含 replay 的文件主要检查 AST、重试策略和内存后端，不能替代真实 Temporal 历史重放。迁移测试使用 SQLite，不能替代 PostgreSQL 迁移/并发验收。任务 V1-01、V1-15。

### F08 / P1：安全扫描显示通过但扫描过程报错

`scripts/check-security-boundaries.sh` 输出 “Security boundary checks passed.”，同时出现 `grep: empty (sub)expression`。该脚本包含 BSD grep 不兼容的空分支表达式，扫描 glob 也需核对。退出码 0 不足以证明所有规则执行成功。应改成明确匹配与错误传播，用临时夹具证明正常内容通过、每种违规内容失败、扫描器报错本身失败。任务 V1-01。

### F09 / P1：默认 E2E 可复用别的项目

`playwright.config.ts` 设置 4173、`reuseExistingServer: true`。本轮端口实际返回其他项目登录页，测试截图显示 AutoJs6，当前源码没有该页面。原结果属于环境污染，不能列为本项目功能失败。独立端口复核见验证结果文件。修复为独占端口、strictPort 和应用身份检查。产品专用 E2E 依赖其配置启用 API，默认套件不应无条件混跑。任务 V1-01。

### F10 / P1：未发现用户现有素材库/商品库连接器

在 services、packages 和 Web 源码中检索 feishu/bitable/lark/source_system/external_id/connector，没有找到对应业务实现。此证据只能说明这些命名下未找到，不能证明所有外部集成绝对不存在。现有库在哪里、使用什么表结构、如何拿附件、如何增量同步均未知。必须先做 V1-03，不能把“本系统能建商品”写成“接上用户商品库”。

### F11 / P2：商品与媒体的两次保存可能部分完成

Web 先更新商品，再调用媒体排序接口。第二次失败时第一次已提交；界面需明确哪些内容保存成功，下一次重试需使用最新 revision。建议首版使用一个原子保存用例，保留现有接口兼容性，新增失败和并发回归。任务 V1-10。

### F12 / P1：前端会话仍为本机固定角色

`apps/web/src/stores/session.ts` 使用固定本机用户，`can()` 恒返回 true；`api/control.ts` 支持开发身份，`OperationsView.vue` 还硬编码了服务器地址和 TLS 指纹。后端已有 JWT/RBAC 检查，因此不能从前端代码直接推断后端权限被绕过；但正式 UI 的登录态、能力提示及环境配置尚需补齐。任务 V1-29 应接入实际会话并移除生产开发身份，分别验证普通用户/管理员/未登录者，服务器信息从环境配置取得。

## 清理决定

保留：392 项 Python 回归的源码、Web/Studio/Kotlin 有效测试、acceptance-target、边界及恢复测试、测试内必要 mock。这些代码有明确验证用途。没有为了显得干净而删除功能测试。

保留历史架构任务 JSON、验收记录和旧状态报告作为历史证据，因为生成器和验收工具仍引用它们；新 README 明确它们不是当前开发计划。不删除设备 SQLite、凭据或媒体原件。工作区不是 Git 仓库，因此本轮采用限定文件 ZIP 备份而不是虚构 commit。

## 工期判断

任务表包含30张实施卡，合计45–84人日；按一人每周5个有效开发日约9–17周。它是规划估算，不是根据代码行数计算出的承诺。估算假设一名能修改 Python、Vue、Kotlin 的开发者，执行器模型由人检查关键合同，并且一台手机可用于回归。平台权限申请、提供外部库访问和审核等待单独计为外部等待，不伪装成开发工期。多个模型并行只允许依赖满足且文件范围不冲突的任务，不能把总人日简单除以模型数量。

先验收“一个来源库 → 一个商品 → 一个闲鱼账号”，随后共享编排接入三内容平台。四个平台仍属于完整 V1 范围；仅做预填或草稿不能将完整 V1 标 done。
