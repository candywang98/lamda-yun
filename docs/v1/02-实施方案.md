# V1 具体实施方案

版本：2026-09-05 重审。以下是待实施设计，除明确标为“已有”的对象外，不声称已实现。

## 1. 首版验收边界与操作定义

完整 V1 包括：接入用户的一套商品来源库和一套素材来源库；Web 选商品/内容、选多个自有账号、预览差异后一次确认；后台排队；闲鱼商品、小红书图文、抖音视频、微信公众号图文分别完成发布并可追踪结果。其他电商平台保留扩展接口，待列出具体平台后单独估算，不能承诺未指明平台可用。

分三次交付，但不偷换完整目标：

| 交付 | 可用结果 | 不足以替代的完整目标 |
|---|---|---|
| A / 闲鱼闭环 | 来源商品、正确图片、指定账号、单次提交、结果对账 | 其他平台尚未完成 |
| B / 内容闭环 | 同一内容包生成小红书图文、抖音视频、公众号文章三个目标 | 每平台需要独立权限与真机/API证据 |
| C / 完整 V1 | 一次确认、多账号队列、部分失败、恢复、release、运行手册 | 草稿或待人工操作不能算公开发布 |

“一键”定义为：内容和账号配置好后，在 Web 的目标预览页一次明确确认即可提交整个计划。执行时没有逐张图片、逐字段复制的操作。准备阶段发现账号变更、素材不匹配或需要平台校验时才暂停让用户处理。首次验收可以逐目标人工确认预览，稳定后采用同一次计划审批绑定不可变快照；不是每个平台都强制新增一个重复审批按钮。

支持三个显式模式：`PREPARE_ONLY`（只预填）、`SAVE_DRAFT`（保存草稿）、`PUBLISH`（发布）。前两者可以作为阶段交付，结果分别为 `PREPARED`、`DRAFT_SAVED`，绝不显示“已发布”。公众号本版目标是文章发布；“群发给粉丝”是另一种副作用，不由文章发布自动触发。

## 2. 主链路

```text
用户现有商品库 / 素材库
  ↓ 来源连接器、字段映射、导入预览、增量任务
PostgreSQL 元数据 + S3 媒体
  ↓ Product / ContentRevision / MediaAsset
Web 发布向导：选择来源版本 → 平台账号 → 覆盖字段 → 校验 → 一次确认
  ↓ 同一数据库事务：PublishPlan + Target + Snapshot + Outbox
统一调度与设备/账号互斥
  ├─ Android 路线：Companion HTTPS → 素材校验 → 平台预填 → commit_once
  └─ 官方接口路线：服务端 Publisher → 上传 → 草稿/提交 → 状态查询
  ↓
Target 回执、平台审核状态、发布地址、证据、人工对账
  ↓
Web 结果列表；可选将结果写回来源库
```

**执行边界** (ADR 0003, ADR 0004)：

- **Companion 直连**：设备任务经 APK 通过 HTTPS 直连 Control API，不依赖开发电脑、USB、ADB 或 Edge 常驻。平台：闲鱼、小红书、抖音。
- **API Publisher**：服务端直接调用官方 API，不需要设备。平台：微信公众号。
- **Edge/LAMDA**：仅用于 Studio 开发调试和布局检查，不是生产执行依赖。与 Companion 互斥，不能同时争抢同一设备。

两条路线复用 PublishPlan/Target/Outbox 和 Temporal 编排，不新建另一套任务系统。平台 API 路线不需要伪造 deviceId，设备执行路线必须有 deviceId；两者共用目标状态和提交账本。

## 3. 先识别来源库，后开发连接器

V1-03 需形成脱敏 `source-profile.json`，逐项记录：

| 信息 | 必须得到的内容 | 缺失时处理 |
|---|---|---|
| 类型 | 飞书多维表格、数据库、NAS/文件夹、S3、已有 API、Excel/CSV 中哪一种 | `SOURCE_UNCONFIGURED`；其余领域任务可继续 |
| 商品主键 | 稳定 recordId/SPU、更新版本、标题、描述、价格、库存 | 主键不稳定则先建立来源 ID 映射 |
| 素材主键 | 稳定记录 ID、附件字段、原文件获取方法 | 缩略图 URL 不当作原件 |
| 权限 | 只读角色、secret_ref、可访问范围、撤销方式 | 不在文档粘贴明文密钥 |
| 同步方式 | 分页、更新时间游标、删除标记、附件 URL 有效期 | 无可靠增量时用完整清单+哈希差异 |
| 冲突策略 | 来源优先/本地覆盖，哪些字段允许编辑 | 默认来源字段只读，本地平台覆盖分开保存 |
| 规模 | 记录数、单文件/总量、视频大小、每天变化量 | 先采样 10 商品+20 素材，最终容量按实测确定 |

不能从“有 feishu-auth-qr.png”推断现有库是飞书。计划先实现统一连接器协议和本地 CSV/文件夹合同夹具，实际来源只做用户正在使用的那一类，避免同时开发六种连接器。

来源同步用例：

1. 校验连接权限，列出表/文件字段；用户保存字段映射版本。
2. 读取一页，转换为规范商品/素材记录，保留原始来源 ID、sourceVersion、内容摘要。
3. 下载原媒体到临时文件；校验大小、类型和 SHA-256 后写 S3 并注册 MediaAsset。
4. 写 `SourceRecordLink` 和内容修订；同来源主键+相同 hash 不产生新 revision。
5. 每页业务事务提交后再推进 cursor；进程崩溃重新读同页不重复建记录。
6. 更新来源内容生成新修订，不改已经提交的 PublishSnapshot。
7. 失效附件 URL 重新从来源获取一次；仍失败记录 `SOURCE_ATTACHMENT_EXPIRED`，不登记 READY。
8. 来源删除先标 tombstone；有发布引用的媒体不物理删除。第一次默认不反向删除来源。
9. 可选回写只更新指定的发布结果列，按 targetId 幂等；回写失败不把已发布状态改成失败。

## 4. 数据模型：复用与最小新增

**已有，必须复用**：ProductRow、ProductMediaRow、MediaAssetRow、MediaTagRow、MediaGroupRow、ContentItemRow、ContentRevisionRow、PublishPlanRow、PublishSnapshotRow、PublishTargetRow、CommitIntentRow、DeviceLeaseRow、MobileTaskRow 及现有账户绑定对象。准确字段以 `db.py` 为准。

**建议新增/扩展**：

| 对象 | 必要字段/约束 | 用途 |
|---|---|---|
| SourceConnection | tenant_id、kind、display_name、secret_ref、mapping_version、status、cursor | 来源连接状态，不保存明文密钥 |
| SourceRecordLink | connection_id、entity_kind、external_id、internal_id、source_version、source_hash、deleted_at | unique(tenant,connection,kind,external_id) |
| SyncRun/SyncError | connection_id、cursor_before/after、成功/失败数、外部 ID、错误码 | 可恢复同步，逐行错误定位 |
| ProductRevision | product_id、revision_no、规范字段和媒体清单、payload_sha256 | Product 当前行只有递增 revision；补历史不可变记录，非重复 Product |
| AccountCapability | account_id、channel、scope、status、expires_at、verified_at、identity_fingerprint | 账号能做什么，区别记录存在与真实登录 |
| MediaDeliveryGrant | task_id、target_id、device_id、delivery_id、manifest_hash、expires_at | 限定设备到具体任务素材；不以同租户授权代替 |
| PublishTarget 扩展 | platform、channel、mode、external_id/url、platform_state、error_code、last_reconciled_at | 统一 Android/API 回执 |
| Commit 账本扩展 | target_id 唯一、snapshot_hash、审批版本、attempt=1、issued_at、consumed_at | 单目标最多一次最终提交许可 |
| ContentRevision.payload | kind、title、body、mediaRefs、platformOverrides | 小红书/抖音/公众号各自覆盖，禁止静默截断 |

Product 金额采用明确币种和十进制定点转换，复用现有字符串接口时用 Decimal 校验，不经浮点；`0.1+0.2` 不得写成浮点结果。首版闲鱼采用单规格商品，类目、成色、运费、发货地作为平台覆盖；暂不扩充 ERP、订单、自动库存扣减。库存更新不能由“发布成功”自动减一。

冻结规则：用户确认时生成目标专属快照，包含来源修订、平台覆盖、每个媒体的 ID/hash/顺序、目标账号指纹、执行方式、适配器版本与发布模式。后续编辑只生成新版本；重启、重试、延迟任务只能读已冻结快照。

## 5. 建议接口与合同样例

以下是拟新增合同，先在 Pydantic/OpenAPI 定义，再生成 TS 类型；若当前已存在同等接口则扩展，禁止维护两种语义相同的入口。

| 方法/路径 | 输入关键项 | 成功/冲突 |
|---|---|---|
| POST `/api/v1/source-connections` | kind、secretRef、mapping | 201；只返回脱敏配置 |
| POST `/api/v1/source-connections/{id}:preview` | limit≤采样上限 | 字段映射结果、逐行错误；不写业务库 |
| POST `/api/v1/source-connections/{id}:sync` | expectedMappingVersion | 202 syncRunId；Idempotency-Key |
| GET `/api/v1/sync-runs/{id}` | — | 进度和游标、错误记录 |
| POST `/api/v1/publish-plans:validate` | source、targets、mode | 每个 target 的 blockers/warnings/previewHash |
| POST `/api/v1/publish-plans`（复用） | source+revision、目标数组、previewHash | 201；同 key 同摘要返回原计划，异摘要 409 |
| POST `/api/v1/publish-plans/{id}:submit`（复用/扩展） | expectedVersion、previewHash | 同事务冻结/审批/outbox；过期预览 409 |
| GET `/api/v1/publish-plans/{id}` | — | 目标列表、部分结果、待处理原因 |
| POST `/api/v1/publish-targets/{id}:reconcile` | reason | 202 只查询，不再提交 |
| POST `/api/v1/publish-targets/{id}:cancel` | expectedVersion、reason | 提交前取消；提交中仅记录请求 |
| POST `/companion/v2/.../commit-permit` | targetId、lease/fence、snapshotHash、预览证据 | 仅当条件满足发一次性许可 |
| POST `/companion/v2/.../result` | eventId、sequence、targetId、结果/证据 | 重放同事件不重复更新 |

`...` 表示须与既有 mobile_routes 命名统一的待定路径，不可直接复制为 URL。正式合同卡必须替换完整路径才可进入实现。

```json
{
  "source": {"kind":"PRODUCT","id":"<真实商品ID>","revision":7},
  "mode":"PUBLISH",
  "targets":[
    {"platform":"XIANYU","accountId":"<真实账号ID>","channel":"ANDROID",
     "deviceId":"<已绑定设备ID>","overrides":{"shippingMode":"FREE","condition":"USED"}}
  ],
  "previewHash":"<服务端校验接口返回值>"
}
```

占位符只用于说明结构，执行脚本必须从 API 实际返回值绑定，不能硬编码猜测 ID。服务端根据 source 类型解析 ProductRevision 或 ContentRevision，绝不通过 ID 字符串外观猜类型。

错误合同至少包含：`SOURCE_UNCONFIGURED`、`SOURCE_AUTH_EXPIRED`、`MEDIA_HASH_MISMATCH`、`MEDIA_NOT_READY`、`ACCOUNT_MISMATCH`、`ACCOUNT_AUTH_EXPIRED`、`UNSUPPORTED_CAPABILITY`、`DEVICE_PERMISSION_REQUIRED`、`DEVICE_OFFLINE`、`LEASE_STALE`、`PREVIEW_STALE`、`LOCATOR_NOT_FOUND`、`USER_ACTION_REQUIRED`、`COMMIT_UNKNOWN`。HTTP 401 认证、403 权限、404 租户内无资源、409 状态/幂等冲突、422 参数错误；平台报错保留原始码并映射稳定内部码。

## 6. 发布状态与重试规则

```text
DRAFT → VALIDATING → AWAITING_APPROVAL → QUEUED → PREPARING → READY
READY + PREPARE_ONLY → PREPARED
READY + SAVE_DRAFT → DRAFT_SAVED（必须验证平台实际保存）
READY + PUBLISH → COMMITTING → RECONCILING
RECONCILING → PLATFORM_ACCEPTED → UNDER_REVIEW → PUBLISHED
RECONCILING → FAILED | UNKNOWN
提交前安全点 → CANCELED
```

上述为业务语义；V1-13 必须给出与现有 PublishState、MobileTask 状态的一一映射和迁移策略。不能直接在前端发明新状态，后端仍返回旧枚举。

| 场景 | 自动处理 | 终态/人工处理 |
|---|---|---|
| 来源读取/下载断网 | 有限退避，最多 3 次；失败保留断点 | 明确失败，不发送残缺内容 |
| 素材 hash 错 | 删除临时文件，重新获取来源；不能进入 READY | 重复失败转人工 |
| 账号不一致/登录失效 | 立即暂停，不自动切换账号 | 用户重新认证后重新校验 |
| 单纯 UI 查找超时 | 准备阶段最多限定重试；写动作依赖后置条件 | 定位仍失败，保留证据 |
| 点击或 API 提交响应丢失 | 不自动再次点击/提交；转对账 | 无结果证据则 UNKNOWN |
| 重复事件/设备重启 | 按 taskId+digest、eventId+sequence 去重 | 不重新启动最终动作 |
| 提交中取消 | 记录取消请求并继续查结果 | 不承诺撤销已发生发布 |
| 平台拒绝 | 记录平台码、内容版本、可修改项 | 用户修改成新修订后创建新计划 |

提交协议具体顺序：

1. APK/官方 Publisher 完成预填，上传预览证据与内容摘要。
2. API 核对快照、账号指纹、审批、设备 fence 和取消状态。
3. 数据库持久化唯一 commit_intent，签发绑定 target/snapshot 的短期许可。
4. APK 在本地持久化 `COMMIT_STARTED`，再执行唯一最终点击；API Publisher 同理先落账再发远端请求。
5. 若本地日志显示已开始但不知道结果，恢复时只执行 reconcile。
6. 上传 receipt 后 API 校验事件来源与序号，更新目标；平台只“接收/审核中”时不显示“公开成功”。
7. 本方案提供的是“最多一次提交尝试 + 不确定结果对账”，不承诺在不支持幂等的外部平台上实现绝对 exactly-once 成功。

多目标策略：一个设备同一时刻一个 Runner；同一账号提交串行；不同设备可并行，首版默认并发 1，可配置上限 2 后验收。锁定顺序统一先账号后设备，API 路线只锁账号。调度锁与数据库租约使用同一权威机制，不能另用前端 busy 标记代替。一个目标失败不回滚已成功目标，计划显示成功/失败/未知/等待数量。

## 7. 手机素材投递与选图

已有 `MediaDelivery.kt`、`MediaGalleryExporter.kt`、`MediaDeliveryCoordinator.kt`，在其基础上完善：

1. 领取任务后解析冻结 media manifest，清单必须绑定 taskId、deviceId、deliveryId、快照 hash、过期时间。
2. 使用流式下载写 `.part`；禁止服务端/手机把大视频一次读入内存。首版允许断点失败后重新下载，不能宣称支持 Range 续传，除非有对应测试。
3. 完成大小/MIME/hash 校验后原子移动；记录每项 READY/FAILED。任务取消、空间不足、签名失效均停止。
4. 通过 MediaStore 导出并保存 `assetId → sha256 → URI → displayName → sortOrder`，清单只允许已有媒体资产，不接受任意路径。
5. 等待目标 App 可读取；选择方式必须有“本次素材”可识别范围。优先指定受控相册/唯一文件标识并核对缩略图，不能假设第 N 个节点恒定。
6. 平台选择器不暴露足以验证身份的信息时，停在人工确认，目标标 `USER_ACTION_REQUIRED`；不能自动退回随意坐标点击。
7. 选择后在平台预览核对数量、顺序、封面及内容。图片压缩后不强求平台输出 SHA 等于原图；用受控导出记录+预览证据确认身份。
8. 清理仅删除本任务创建的 URI；保留期建议成功 24h、失败 7d（可配置提案），绝不删除用户已有照片。重启后仍能找到并清理自己创建的文件。

关键验收：相册原有 30 张照片、本任务 3 张图（A/B/C），中途再加入 D；最终仍是 A/B/C 顺序。重复领取不重复导出，媒体 hash 错不进入选择器；100MB 视频测试用于工程容量，不代表任何平台格式上限。

## 8. 四个平台实施流程

### 8.1 闲鱼：商品发布

默认利用现有 APK 路线；官方 API 可作为条件分支，须先验证用户服务商资质和具体商品发布权限，不能把闲鱼小程序订单 API 当成通用商品发布 API。

步骤：核对账号 → 校验商品标题/描述/Decimal 价格/类目/成色/运费/发货地/图片 → 打开卖闲置入口 → 进入发布页 → 选精确素材 → 填字段 → 读回价格和运费 → 核对账号与预览 → 申请 commit permit → 点击一次发布 → 识别审核/成功/拒绝 → 在当前账号商品列表或详情核对标题、图、价格 → 保存商品外部 ID/链接（可获取时）与截图。

特殊处理：权限弹窗、草稿恢复、价格面板和键盘分别有后置条件。不能只查到“发布”二字就点击；必须限定目标包、当前页面、节点唯一性。没有证据确认终态时 UNKNOWN。定位器版本先锁定本机 7.27.90，其他版本未跑过保持不支持。

### 8.2 小红书：图文笔记

路线探测先于实现：官方分享 SDK 用于把内容带到客户端，不可把“成功唤起分享”算成“笔记已发布”。如当前应用获准的官方能力足以完成需求可优先使用；否则按已授权账号的受控 APK UI 路线实施并做版本验收。

步骤：ContentRevision 生成图文覆盖 → 校验标题/正文/图片数量与比例（限制来自当时实际平台能力配置）→ 核对登录账号 → 导出/选择图片并验证顺序 → 填标题正文话题 → 预览 → 一次提交 → 等待审核或发布结果 → 本账号笔记列表核对内容与时间 → 保存笔记 ID/链接或证据。

首版先验收图文，视频笔记作为后续增量；本机 8.50.1 为首个兼容版本。登录核验需要用户操作时暂停，不把无障碍授权当成平台授权。无法验证身份或无法验证发帖结果不开放无人值守 PUBLISH 模式。

### 8.3 抖音：视频

优先验证官方视频上传/创建权限及用户 OAuth 授权；官方创建视频文档说明需要 `video.create`，发布后可能审核，并要求用户明确感知代发操作。没有获得实际权限时不能宣称 API 已接通。

API 路线：取服务端 secret_ref → 校验 scope/过期 → 上传视频获得 video_id → 保存上传回执（上传非发布）→ 生成标题/封面/话题 → commit_intent → 调一次创建 → 保存 item_id/结果 → 查询审核/可见状态。

Android 路线：核对账号 → 选择指定视频 → 等待导入/处理 → 校验封面、标题、可见范围 → 提交一次 → 查询个人作品页。API 提交一旦可能发生，不得自动切到 APK 再发；跨路线切换必须发生在 commit_intent 前。

不要直接写死网上转述的上传上限；建立 `PlatformCapability` 并记录文档日期、账户 scope、文件上限和适配器版本，验收超限输入明确阻断。首版先验收单视频，不把抖音图文能力和视频 scope 混用。

### 8.4 微信公众号：图文文章

先确认是哪个公众号、什么主体与当前后台接口权限，再决定官方接口或管理端辅助路线。手机装了微信和已经登录个人微信都不能代替公众号发布能力。

拟定官方路线：上传封面及正文图片 → HTML 安全清洗和图片地址替换 → 创建草稿 → 草稿预览 → 明确发布审批 → 申请提交许可 → 调发布 → 保存发布 ID → 查询状态 → 记录文章 ID/URL。草稿创建、文章发布、粉丝群发在数据模型和 UI 上分别命名。

本轮微信官方文档抓取没有拿到可核验正文，所以上述接口流程是待验证实施假设，不把历史接口名、权限资格或配额视为 2026-09-05 的已核事实。V1-26 必须从用户后台当前权限和官方文档取得证据后锁定端点/字段；权限不足时交付草稿+显式人工处理，完整发布验收保持 blocked，不能将其隐藏为成功。

若需要管理端 UI 辅助，另记录所用管理工具/浏览器和版本，不能假设微信聊天界面能直接发布公众号。群发不在该适配器里暗中调用。

## 9. Web 与 APK 界面拆分

Web 首版只突出六个入口：来源库连接、商品库、素材/内容库、账号设备、发布向导、发布记录。已有 134 项目录保留在高级/历史入口即可，不再优先填充竞品元信息。

发布向导：

1. 选商品修订或内容修订，显示来源库和最近同步时间。
2. 按平台展示可用账号；账号能力不足/设备离线解释具体原因。
3. 平台覆盖编辑：闲鱼价格/运费，小红书图文，抖音视频/封面，公众号文章/封面。
4. 校验页展示每个目标预览，失败字段定位到具体平台；禁止静默丢图、截标题或更换账户。
5. 点击一次“确认发布 N 个目标”，本地保存 idempotency key 到取得 planId；网络重试复用同 key，用户主动新建批次才生成新 key。
6. 跳转独立 planId 详情：显示素材投递、执行阶段、当前账号、证据、审核状态、结果地址、人工处理按钮。刷新页面不丢状态。

APK 首页只需显示：绑定服务器环境、设备 ID、版本、心跳时间、无障碍/通知/存储/前台服务状态、当前目标账号、执行步骤、停止自动化按钮、最近错误。测试按钮置于 debug 构建，不让 release 带任意动作调试入口。

## 10. 验收用例与发布门槛

| 编号 | 输入/故障 | 预期结果 |
|---|---|---|
| A01 | 同来源记录同步两次 | 业务 ID 不变，不增重复 revision/media |
| A02 | 同外部 ID 不同租户 | 数据隔离，媒体不可跨租户读取 |
| A03 | 游标提交前进程退出 | 重跑无丢失无重复，页事务一致 |
| A04 | 商品编辑成功但媒体更新失败 | 原子回滚或明确部分结果，不能误报全部保存 |
| A05 | 计划确认后来源库修改 | 已确认目标继续使用旧快照，新计划显示新版本 |
| A06 | 相册干扰图/相机入口/倒序 | 只选本次素材、顺序正确 |
| A07 | 手机切到另一个平台账号 | `ACCOUNT_MISMATCH`，无提交动作 |
| A08 | 双击发布/请求超时重试 | 同一个 plan/target，最多一次最终动作 |
| A09 | 提交后断网或杀进程 | 恢复只对账；无法确认则 UNKNOWN |
| A10 | 重复/乱序/旧 fence 回执 | 去重或拒绝，终态不倒退 |
| A11 | 取消准备中目标 | 不触发提交，清理本任务文件 |
| A12 | 取消提交中目标 | 不承诺撤回，继续对账显示实际结果 |
| A13 | 四平台批次一个失败 | 其他目标正常；汇总部分失败，不重发成功项 |
| A14 | 断开 USB、停开发 Edge、手机用独立网络 | APK 能收取任务、回传；不依赖本机端口转发 |
| A15 | 平台回传“审核中” | 显示审核中；不提前标公开发布 |
| A16 | 公众号只有草稿权限 | DRAFT_SAVED / 权限阻塞，不能称发布完成 |
| A17 | 媒体 hash 错、空间不足、URL 过期 | 明确错误，平台不选图、不提交 |
| A18 | release 安装后重启/升级 | 原绑定与本地任务恢复，签名和版本可核对 |

每平台至少完成一条真实成功发布及一组提交不确定性/失败验收；最终外部发布使用用户明确选定的内容与账号。公开发布有实际副作用，开发测试默认只预填，真实验收的提交必须由发布界面的授权确认触发。

验收证据必须包含：源码/构建摘要、服务部署版本、Android 与目标 App 版本、task/plan/target ID、脱敏账号指纹、快照 hash、提交账本、事件序号、截图/页面证据、外部 ID/URL（可获取时）、失败步骤和实际命令退出码。没有证据不能将任务改 done。
