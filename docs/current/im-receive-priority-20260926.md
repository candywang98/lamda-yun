## 顺序与验收

1. 单机：确认业务 APK、无障碍实际 Bound、闲鱼登录状态、NOTIFICATION 配置、有效绑定；接收用户自行安排的外部账号真实测试消息，核对手机采集、服务器入站和网页的同一通知内容、来源设备及时间。通知摘要可用于区分会话通知与系统通知，完整聊天正文不是本轮前置条件。不能用模拟通知、插库、旧记录或代理代发冒充通过。
2. 三机：沿用云端 `deviceId + platform + peerKey` 会话隔离和包含 deviceId 的持久去重键，验证同名联系人不会跨设备合并。ADB serial 不是业务身份。
3. 平台扩展：闲鱼先验收。当前 Android `ImNotificationIntake.observe`、`ImOutboxStore.enqueue` 与后端 `ImMessageIn`/`ImService.ingest` 仅接受闲鱼。网页列出其他平台不是端到端支持证明；不得仅凭亮屏认定微信、小红书、抖音已接通。
4. 消息分类（当前开发优先）：网页提供用户消息、系统/营销、待确认及全部分区；保留原始通知和 Jev 原始预测/置信度，支持人工纠正、恢复自动及重新识别。模型置信度不是“真实人类身份”的证明。未知/失败/低置信度不得静默丢弃。合同见 `contracts/phase1/pa-im-notification-classification-v1.md`，版本 `im-notify/20260926.1`。Android 移除通知入口的昵称/关键词硬过滤，不扩展 DUTY 导航和生产平台。

禁止真实发送、回复任务、发布、删除、改价、评价及自动转发。本轮不启用 DUTY 自动导航，不因“只收不发”而绕过设备锁、用户权限或网页认证。
