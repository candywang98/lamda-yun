## Root Cause Evidence

The protocol mismatch is confirmed by deployed source and installed client
source:

- Deployed `order-delivery-557f547` hashes match the corresponding Git source
  for `app.py` and `mobile_service.py`.
- Its maintenance claim path raises `ConflictError("device is in maintenance
  and cannot claim tasks")` and the shared handler returns HTTP `409` with an
  eight-field `application/problem+json` envelope: `type`, `title`, `status`,
  `code`, `detail`, `correlation_id`, `retryable`, and `fields`.
- `CloudTaskClient.request` preserves the whole response string in
  `CloudHttpException.responseBody`.
- Installed `a3eb419` requires `body.length() == 1`; therefore the real envelope
  cannot match the maintenance deferral classifier. The outer sync-loop handler
  treats the resulting `409` as non-retryable and calls `stopSelf()`.

The response-shape incompatibility is **CONFIRMED**. Linking the contextual
non-target-attributed journal row to this exact PID is a **high-confidence
inference**, because the target log does not print the claim response body or a
request correlation id.
